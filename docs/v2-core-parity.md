## Structured memory-selector generation

The V1 memory selector's `format: json_schema` requires native structured output. Asking for JSON in prose is not equivalent.

- HTTP: `POST /api/session/:sessionID/generate-object` with `{prompt, schema}` returns `{data: {object}}`.
- Public Promise plugin API: `ctx.session.generateObject({sessionID, prompt, schema}, requestOptions?)` resolves to **`{object}`**. The generated client and in-process adapter unwrap the wire `data` field once.
- The method uses the supplied fork's configured agent, model, system instructions and history. It runs the `context` hook followed by the `generate` hook, plus normal model/HTTP request hooks. Ordinary text generation keeps its existing behavior.
- Native `LLM.generateObject` forces the synthetic `generate_object` tool. No Session tools execute. Raw JSON Schema is compiled through the same Effect codec used by tool-input validation; output is decoded with excess-property errors enabled. Missing output calls, malformed JSON, missing required fields, invalid values and forbidden extra fields are rejected.
- Generation does not admit a prompt, alter history, or mutate the parent/fork. The real HTTP/provider test compares durable tables and context before and after each call.
- Promise in-process API cancellation forwards `requestOptions.signal`, including first-argument options on no-input methods. A real SDK plugin activation test proves the public call unwraps to `{object}`, cancellation rejects the Promise and closes the provider read, activity reaches zero before fork removal, and parent context remains unchanged.

## Complete plugin history

`ctx.session.context({sessionID})` intentionally returns the current model window, beginning at the latest completed compaction. It is not a replacement for the V1 full-message history API.

Promise and Effect plugins expose the existing `MessageApi` as `ctx.message.list`. It returns **`{data: messages, cursor: {previous?, next?}}`**, including pre-compaction rows and unfinished assistant output. The native host and existing HTTP message handler share `SessionMessagePage.list`, preserving the same opaque cursors and ordering without a Core runtime dependency on Protocol or Client.

For a chronological full scan, request `{sessionID, limit: 200, order: "asc"}` first. Follow `cursor.next` with `{sessionID, limit: 200, cursor}` and no `order`; stop when `data` is empty. Preserve the same `type` filter when following cursors. Promise calls accept `RequestOptions.signal` for cancellation.

Legacy memory/peers `messages` and `message(id)` adapters use these raw pages. Model-context transforms and unchanged-read suppression keep using current context intentionally. No model-history selection, compaction behavior, transfer filtering or HTTP routes change.

The actual SDK-plugin regression compares native pages with HTTP results in both orders at page sizes 1, 2, 3 and 8. It covers reverse pagination, exact IDs without duplicates, pre-compaction rows, running partial assistant output, type filters, cross-session anchors and invalid-cursor messages. An already-aborted signal is rejected before synchronous native reads begin; a subsequent uncancelled read still succeeds without mutation.

History followup checks: existing HTTP pagination tests passed (2 tests, 20 assertions); actual plugin history plus generation-cancellation tests passed ten times (20 tests, 1,970 assertions). Core Promise-tool regressions passed (3 tests, 6 assertions). Core, Plugin and Server typechecks passed.

## Captured limits

- Cancelling a pending steer while the runner is preparing context can leave one redundant model call against older history. Existing tests establish that behavior; withdrawal does not broaden it. Delivered-prompt withdrawal uses a separate output fence and interrupts the active drain.
- Entirely new config-root topology still depends on upstream Config discovery/reload. Skills added or repaired beneath registered sources recover on lookup without waiting for filesystem watchers.
- Core exposes public skill diagnostics and tool-facing failure details. The CLI diagnostics command belongs to the interface stream.
- V1 history refresh is offline maintenance only. The history stream owns importer semantics; the manager stops the isolated candidate server and verifies its process is gone before opening the copied database with a Database + Global + V1Migration-only runner. No live-server refresh endpoint is added.
